用 LLM 构建 Coding Agent Lesson 01

Agent Loop 的本质

为什么一个 coding agent，剥到最里层，就是「LLM 在一个循环里调用工具」

你的目标是从零写一个 coding agent。在写任何代码之前，你需要一张能钉在脑子里的心智图。 这节课只讲一件事，但它是后面所有课的地基：agent 的核心不是一个复杂系统，而是一个简单的循环。

先破除一个误解

很多人以为 "AI agent" 是某种庞大、神秘的架构。Anthropic 在他们那篇被广泛引用的文章里给了一个反直觉但极其重要的判断： 最成功的 agent 实现，用的都是简单、可组合的模式，而不是复杂框架。

他们对 agent 的定义只有一句话（值得你背下来）：

“Agents are typically just LLMs using tools based on environmental feedback in a loop.”

Agent 通常就是：LLM 根据环境反馈，在一个循环里使用工具。

拆开这句话里的四个词，你就拿到了整张地图：

  • LLM —— 大脑。它负责「想」：现在该做什么。
  • tools（工具） —— 手脚。LLM 自己不能读文件、跑命令，工具是它伸向世界的接口。
  • environmental feedback（环境反馈） —— 眼睛。工具执行后返回的结果（文件内容、报错、命令输出），让 LLM 看到「刚才那步的后果」。
  • loop（循环） —— 心跳。上面三件事不是做一次就完，而是反复进行，直到任务完成。

Loop 长什么样

把上面四个词按时间顺序排开，就是 agent loop。以「帮我修复这个 bug」为例：

1 LLM 思考并决定行动 —— 模型读到任务与当前上下文，输出「我要调用 read_file 读一下 utils.ts」。这一步产出的不是最终答案，而是一个工具调用请求。
↓
2 你的代码执行工具 —— 注意：执行工具的是你写的程序，不是 LLM。LLM 只是「点单」，真正去读文件的是你的循环代码。
↓
3 把结果喂回给 LLM —— 文件内容作为「环境反馈」追加进对话，再次发给模型。这是 ground truth：模型据此判断进展。
↺
回到第 1 步：LLM 拿着新信息，再想下一步

就这样转圈：想 → 做 → 看结果 → 再想。每一圈 LLM 都掌握着「下一步做什么」的决定权。 直到某一圈，模型判断任务完成，不再请求工具，而是直接输出最终回答 —— 循环结束。

这就是 agent 和普通 chatbot 的唯一本质区别。 Chatbot 是「问一次，答一次」。Agent 是「在循环里，自己决定要转多少圈、每圈调什么工具」。 循环里那个「谁决定下一步」的答案是模型自己 —— 这就是 “agentic” 一词的全部含义。

为什么这对你（写 TS agent）很重要

Anthropic 明确建议：先直接用 LLM API，别急着上框架。因为「很多模式几行代码就能实现」， 而框架会用抽象层盖住底层的 prompt 和响应，反而更难调试。

对你意味着：你完全有能力从零写出这个 loop。它在 TypeScript 里的骨架，粗略看就是一个 while 循环 —— 循环体里调一次 LLM API，看它是否要求调用工具，若要就执行并把结果塞回消息列表，然后继续下一轮。 后面几节课我们会把这个骨架一行行填出来。今天你只需要记住这个形状。

一个常见的初学者困惑，先给你打预防针：LLM 从不自己执行工具。 它只是在回复里说「我想调用这个工具、参数是这些」。真正执行、拿到结果、决定要不要把结果给它看的， 永远是你写的循环代码。这个「控制权在你手里」的事实，是后面理解安全、权限、错误恢复的前提。
